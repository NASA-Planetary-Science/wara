# Associated Particle Imaging (API)

Associated Particle Imaging tags each 14.1 MeV neutron from a D–T generator by
detecting its companion alpha particle in a position-sensitive YAP detector. The
alpha hit fixes the neutron's *direction*, and the alpha–gamma time difference
fixes *how far* along that ray the neutron-induced gamma was produced — so every
detected gamma can be placed in 3D inside the sample. wara's API tools load these
coincidence event lists, explore them through linked energy/time/position views,
and reconstruct the interaction points.

```{note}
This is a different "API" from the autogenerated [API Reference](autoapi/index)
(the Python module docs). Here it means the imaging technique.
```

## Data layout and loading

API runs are stored as **per-event parquet files**, one run per
`RUN-YYYY-MM-DD-NNNNN` folder. wara locates runs by date and run number using the
paths listed in `data-path.txt` (see [Installation](installation.md#data-path-configuration)).

Load a run's events into a pandas DataFrame with {py:mod}`wara.read_parquet_api`:

```python
from wara import read_parquet_api as rpa

df = rpa.read_parquet_file("2024-03-15", 12, ch=4)   # date, run number, channel
```

`ch` selects the detector channel (e.g. `4` = LaBr, `5` = non-LaBr in the legacy
flag scheme); pass `flood_field=True` or `ch=None` to keep all events. Each row
is one coincidence event with the columns the rest of the tools expect:

| Column | Meaning |
|--------|---------|
| `energy` | Gamma-ray energy (or channel) |
| `dt` | Alpha–gamma time difference |
| `X2`, `Y2` | Alpha interaction position on the YAP face (dimensionless corner ratios) |
| `channel` / `LaBr[y/n]` | Detector identifier |

```{tip}
If a run was acquired in time-misaligned chunks,
`rpa.read_parquet_file_time_aligned(date, runnr, ch=...)` aligns each chunk's
`dt` on its most prominent peak before concatenating.
```

## The three linked views

API analysis revolves around three histograms of the same event set: the gamma
**energy** spectrum, the alpha–gamma **time** (`dt`) distribution, and the
alpha **X–Y** image. `initialize_plots` draws all three onto axes you provide:

```python
import matplotlib.pyplot as plt
from wara import read_parquet_api as rpa

fig, (ax_e, ax_t, ax_xy) = plt.subplots(1, 3, figsize=(18, 5))
rpa.initialize_plots(df, ax_g=ax_e, ax_t=ax_t, ax_xy=ax_xy)
```

The individual `plot_energy_hist`, `plot_time_hist`, and `plot_xy` helpers are
available if you want one panel at a time.

## Selecting regions

The power of API is conditioning one view on a cut in another — e.g. the energy
spectrum from only a chosen region of the sample, or the X–Y image of only a
single gamma line. {py:mod}`wara.apicalc` provides DataFrame filters that return
a sub-DataFrame you can re-plot or reconstruct:

| Helper | Cut |
|--------|-----|
| `dfe(df, erange)` | energy window |
| `dft(df, trange)` | time (`dt`) window |
| `dfxy(df, xrange, yrange)` | X–Y region (`dfxy_exclude` for the complement) |
| `dfet(df, erange, trange)` | energy **and** time |
| `dfxye(df, xrange, yrange, erange)` | position **and** energy |
| `dftxy(df, xrange, yrange, trange)` | position **and** time |

```python
from wara import apicalc as ac

roi = ac.dfxy(df, xrange=(-0.3, 0.3), yrange=(-0.3, 0.3))   # central tile
rpa.plot_energy_hist(roi, ebins=2048, ax=ax_e)             # its energy spectrum
```

## 3D position reconstruction

Given the alpha position and `dt`, `api_xyz` reconstructs the neutron-interaction
point `(X, Y, Z)` in centimetres for every event:

```python
from wara.apicalc import api_xyz

X, Y, Z = api_xyz(df, det_pos=(-18.0, 0.0, -25.0))   # gamma-detector centre, cm
```

This is the full-rigor model: relativistic alpha/neutron speeds, the
center-of-mass correction (the alpha and neutron are back-to-back only in the
reaction CM frame), and the exact gamma-detector vector. The coordinate origin is
the neutron source, with `+z` up and `-z` toward the sample. `api_xyz_simple` is
a legacy non-relativistic, point-source variant.

```{seealso}
The geometry, kinematics, and the reconciliation of the different reconstruction
formulations are derived in detail in the accompanying note:
{download}`API 3D position reconstruction <API_position_reconstruction.pdf>`.
```

## In the GUI

The **API** tab in the navigation rail is the interactive version of everything
above. It loads a run's parquet data into the three-panel energy/time/X–Y figure,
applies **live filters** across the panels, and lets you:

- **send a selected energy spectrum to the Spectrum tab** for peak fitting and
  isotope identification,
- pop out a **3D volume view** of the reconstructed hit cloud,
- run **time-slice fits** across the `dt` distribution, and
- pick **X–Y tile selections** to build energy-region-vs-position profiles.

For the full API of these modules, see {py:mod}`wara.read_parquet_api` and
{py:mod}`wara.apicalc` in the API reference.
